# Glyph · Compose — 离线像素字形排版

Vue 3 + TypeScript + Vite 的单页离线工具：编辑 2～40 个同高黑白像素字形
（每个宽/高 1～32），输入长度 ≤ 80 的字串，按「黑像素不重合」规则紧凑排版，
输出全部字形位置、黑像素最小包围盒，以及**按字形来源标色**的合成图，
并可导出同源的 PNG 与位置 JSON。

## 排版规则

- 首字左边缘 `x = 0`（`y = 0`，所有字形同高顶对齐）。
- 此后每字左边缘**严格大于**前一字左边缘，取满足条件的**最小整数 x**：
  该位置下本字任何黑像素都不与**任何已放置字形**的黑像素重合。
- 空白像素允许互相覆盖 —— 因此字形外框可以交叠，不会因凹口留白而产生缝隙。
- 碰撞检测对全部已放字形逐行进行，而不是只检查相邻两字：
  否则第三个字可能撞上第一个字的伸出笔画（见下方反例）。
- 黑像素最小包围盒只包住真正的黑像素；整张合成图没有任何黑像素
  （含空串、或字串只含全空字形）时包围盒记为 **`EMPTY`**。
- 缺失字符、非法位图（行数不符、非整数、超出宽度位宽）、尺寸/数量越界、
  字串超长等情况：**保留当前编辑内容，但撤销旧排版**（界面显示错误且不产出布局）。

### 为什么不能只看相邻字

`A` 宽 5 但只有最右列一个黑像素（长伸出笔画），`B` 宽 3 全黑，`C` 宽 1：

```
A: . . . . █      B: █ █ █      C: █
```

- 只与相邻字比较：x(A)=0, x(B)=1（B 的黑像素落在 1..3），x(C)=4 ——
  而 A 的黑像素恰在第 4 列，**C 撞上了 A**。
- 本实现与全部已放字形比较：x = [0, 1, 5]。

## 算法

`src/core/layout.ts`

- 每行用一个 `bigint` 位掩码 `occupied[r]` 记录已放置黑像素所在列。
- 候选 x 从 `prevX + 1`（首字为 0）递增，检测
  `occupied[r] & (glyphMask[r] << x)`；搜索上界为已放置外框右边界，
  该位置必然无碰撞，故一定终止。
- 顺带累计黑像素的行列极值得到最小包围盒。

## 测试

```bash
npm test
```

`src/core/layout.test.ts`（Vitest）包含：

- **逐像素穷举偏移对拍**：另写一份刻意朴素的 `Set<行列>` 参考实现
  （`src/core/reference.ts`），150 组随机字形/字串逐偏移核对 x、来源、bbox、覆盖范围；
  并对每个字断言「下界到实际 x 之间的每个整数偏移都必然碰撞」（最小性）
  与「最终黑像素集合两两不相交」（全局无碰撞）。
- 长伸出笔画专项：验证正确结果 `[0,1,5]`，同时用只看相邻字的实现复现反例 `[0,1,4]`。
- 全空字形：空白覆盖下 x 仍严格 +1、bbox 为 `EMPTY`、空串范围 `0×H`、PNG 全透明。
- 重复字符共享来源与颜色。
- 非法输入（缺字、坏位图、越界、重复字符、超长，含 emoji 代理对按码位计数）。
- PNG 用 node:zlib 解压回像素，逐像素核对颜色等于来源色，并验证 JSON 与 PNG 同源。

## PNG / JSON 同源导出

- PNG 为零依赖手写编码器（`src/core/png.ts`，8-bit RGBA + zlib stored block，
  自算 CRC32/Adler32）。
- 界面中 `compose()` 只在一个 `computed` 里执行一次；
  `exportSnapshot()` 把同一次排版结果同时渲染为 PNG 与位置 JSON，
  两个导出文件保证来自同一布局。
- JSON 中 `bbox` 为包围盒对象或字符串 `"EMPTY"`。

## 开发

```bash
npm install
npm run dev      # 本地开发
npm test         # 运行测试
npm run build    # 类型检查 + 生产构建（纯静态，可离线打开 dist/）
```

编辑内容通过 localStorage 自动保存，刷新不丢失。
